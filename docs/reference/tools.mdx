This page is generated from `lib/tools/registry.ts` by `scripts/generate-tool-docs.ts`. To change it, change the tool and run `pnpm docs:tools`.

The connector exposes 16 public tools at `https://cleared-mcp.vercel.app/mcp`. They need no account and no token.

Every tool call goes through the same pipeline: a size limit, the personal-data guard, schema validation, the tool, and an output check. Every result that states a fact carries `sources`, and most carry a `disclaimer`. Errors come back as a tool result with `isError: true` and a plain message, never a stack trace.

To call a tool without an agent, `POST` its input as JSON to `/api/tools/<name>`. The playground at [/try](https://cleared-mcp.vercel.app/try) does exactly that.

## Find roles and check them

Start here. `search_defense_roles` returns the `role_id` and `company_slug` the other tools take.

### `search_defense_roles`

**Search defense-tech roles.** Searches live defense/hard-tech roles from the a16z speedrun Talent Network's public API. Each result includes requirement signals labeled 'stated' (a verbatim quote from the posting) or 'inferred' (a pattern-based judgment call to confirm with the employer) — never a guess presented as fact. Filter by level, min_experience, employment_type (e.g. internship) and company upstream; clearance and itar_only are checked on each posting's text, up to 25 postings per call. Every result says how many postings match (matchedTotal) and which of them this call examined (examined); pass nextCursor back as cursor, with the same filters, to examine the rest. Positions can shift slightly if postings are added or filled between calls.

Read-only: it reads or computes and changes nothing.

### `prepare_signed_attestation`

**Prepare a signed self-attestation.** Wraps a self-asserted status claim (clearance level, citizenship status, and/or availability date — no free text) in a signed, shareable credential your OWN agent produces and signs locally; this server never sees or holds any private key. To use: (1) if you don't already have one, generate an Ed25519 keypair once and reuse it across attestations (e.g. in Node.js: const &#123;publicKey, privateKey&#125; = crypto.generateKeyPairSync('ed25519')) — never send the private key anywhere, including to this tool. (2) Build signed_payload as the exact JSON string &#123;"claims":&#123;...&#125;,"issued_at":"&lt;current UTC ISO-8601 timestamp&gt;"&#125;. (3) Sign its UTF-8 bytes (crypto.sign(null, Buffer.from(signed_payload), privateKey)), base64-encode as signature_base64. (4) Export the public key (publicKey.export(&#123;type:'spki',format:'der'&#125;).toString('base64')) as public_key_base64. (5) Call this tool with claims, issued_at, signed_payload, signature_base64, public_key_base64 — claims/issued_at are cross-checked against signed_payload's own content, and the signature is verified before anything is returned. Proves which key signed the claim and that it hasn't been altered since — not when it was signed (issued_at is the signer's stated time, which the signature cannot prove; verify_signed_attestation flags a stated time older than 30 days), and never that the claim itself is true. Reusing the same keypair lets a recruiter recognize repeat signals from the same pseudonymous source without ever learning who you are. Loosely modeled on the W3C Verifiable Credentials data shape, not a certified implementation of it.

Read-only: it reads or computes and changes nothing.

| Input | Type | Required | Notes |
| --- | --- | --- | --- |
| `claims` | object | yes |  |
| `issued_at` | string | yes |  |
| `signed_payload` | string | yes | The exact JSON string &#123;"claims":&#123;...&#125;,"issued_at":"..."&#125; that was signed, byte-for-byte — not reconstructed by this tool. |
| `signature_base64` | string | yes | Ed25519 signature of signed_payload's UTF-8 bytes, base64. |
| `public_key_base64` | string | yes | Ed25519 public key, SPKI/DER, base64-encoded. |

### `verify_signed_attestation`

**Verify a signed self-attestation you received.** The recipient's side of prepare_signed_attestation: checks whether a credential someone handed you was really signed by the key it names, and hasn't been altered since. Pass signed_payload, signature_base64, and public_key_base64 exactly as they appear in the credential. Returns the decoded claims, the signer's stated time with its age (flagged when older than 30 days or in the future), and a short key fingerprint, so you can recognize the same pseudonymous signer across separate credentials. A valid signature proves which key signed and that nothing changed since — not when it was signed (the time is the signer's own statement), and never that the claim itself is true; only an employer's FSO can verify actual clearance status.

Read-only: it reads or computes and changes nothing.

| Input | Type | Required | Notes |
| --- | --- | --- | --- |
| `signed_payload` | string | yes | The exact signed_payload string from the credential you were given — byte for byte, not re-serialized. |
| `signature_base64` | string | yes | signature_base64 from the credential. |
| `public_key_base64` | string | yes | public_key_base64 from the credential (Ed25519, SPKI/DER, base64). |

| Output field | Type | Notes |
| --- | --- | --- |
| `signatureValid` | boolean |  |
| `claims` | object or null |  |
| `issuedAt` | string or null |  |
| `statedTimeCheck` | object or null |  |
| `keyFingerprint` | string |  |
| `whatThisProves` | string |  |
| `whatThisDoesNotProve` | string |  |
| `sources` | array of object |  |
| `disclaimer` | string |  |
| `ignoredInputKeys` | array of string | Input keys this tool does not take, dropped unused and not stored. |

Example input (shape only: a real signature cannot be shown):

```json
{
  "signed_payload": "<signedPayload from the credential>",
  "signature_base64": "<signature from the credential>",
  "public_key_base64": "<public key from the credential>"
}
```

## Anonymous interest pool

The one tool that writes. Call it only after the person agrees, every time.

### `contribute_anonymous_signal`

**Contribute to a role's anonymous aggregate signal.** Opts this one role-interest into an anonymous, aggregated signal pool other tools (get_aggregated_signal) can read back as a rounded percentage once enough people have contributed — never as an individual record. Carries no name, contact info, or identifier of any kind, only closed-enum buckets (clearance_level, years_experience_bucket) you explicitly choose to include. Call this only when the candidate has explicitly agreed to contribute — it is never implied by calling any other tool.

### `get_aggregated_signal`

**Read a role or company's aggregated anonymous signal.** Reads back the anonymous signal pool contribute_anonymous_signal writes to, as percentages rounded to the nearest 5 — never an individual record, and never before at least 5 people have contributed for this exact role or company (a k-anonymity floor: below that, or for any specific bucket value with fewer than 5 contributors, this returns nothing for it rather than a number that could single someone out). It updates only in steps of 5 contributions and gives the total as a band, so comparing two reads can never isolate one new contributor. Pass exactly one of role_id (that specific posting only) or company_slug (every contribution across all of that company's postings).

Read-only: it reads or computes and changes nothing.

| Input | Type | Required | Notes |
| --- | --- | --- | --- |
| `role_id` | string | no | A role id from search_defense_roles (roles[].id). Search first if you don't have one. |
| `company_slug` | string | no | A company slug from search_defense_roles (roles[].companySlug) — a guessed slug from a company's common name often won't match. |

## For hiring teams

### `generate_interview_guide`

**Generate a structured interview guide for a role.** Generates a structured-interview question set (behaviorally-anchored evaluation guidance per question, never a numeric score) built only from a role's public posting text — for a startup's own human panel to run themselves.
